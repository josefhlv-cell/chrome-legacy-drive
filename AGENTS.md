# Architecture rules
- Smart Capture showroom inference uses an authenticated Lovable AI endpoint only for the main shot; retain original_url, composite only processed_url, persist attempt/result locally and claim each paid request in storage to prevent upload retries from repeating inference.
- Bundle the installed ONNX runtime rather than externalizing its bare imports, because the browser requires resolvable runtime modules for local segmentation.
- Public vehicle lists fetch at most one embedded vehicle_images row ordered by is_main DESC, sort_order ASC, id ASC; admin and detail galleries remain complete, avoiding full-gallery transfer for cards.
- Do not schedule showroom-batch while bulk generation is disabled; manual primary-photo generation remains available without idle polling.
- Admin-uploaded Show Room photos live in vehicles.show_room_images as an ordered JSON array with a separate show_room_enabled flag; use only for public detail galleries, never vehicle_images or listing fields, to preserve original-photo behavior. Storage removals must validate the dedicated show-room/{vehicleId}/ prefix and commit metadata first; compare-and-swap prevents concurrent admin overwrites.
- Smart Capture keeps one guided 20-shot sequence; session metadata stores skipped steps and capture progress without requiring schema changes.
- Accepted capture photos and their progress share a durable IndexedDB record; advance only after the local transaction commits, never after network upload or advisory analysis, to survive abrupt browser closure.
- Capture readiness is checked independently of media events; JPEG callbacks and local persistence have bounded recovery paths so stalled browser APIs cannot silently lock capture controls.
- Mobile camera tracks are stopped on page hiding and reacquired by a user gesture; stale async camera requests must stop their tracks to avoid iOS frozen previews and camera leaks.
- Mobile Smart Capture is capture/handoff only; desktop uses the same session IDs for review, completion and export.
- Capture completion waits for durable remote photos and progress, marks metadata as finished, then clears the active-session pointer without deleting the saved review session; this prevents mobile auto-resume while retaining desktop export.- Showroom composites are generated only for a vehicle's primary photo (is_main → lowest sort_order → id), enforced in both UI and runShowroom; bulk showroom-batch is disabled to keep costs and catalog consistency under control. The fixed background is `public/assets/showroom/master_showroom_background.jpg` (1500×846, never stretched) and must not be regenerated or cropped.
